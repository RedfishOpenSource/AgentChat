配置 Agent，监听消息，审核答复

本文档与案例直接保存在项目 frontend/public/guide.html，随前端构建发布；阅读、复制案例不写入 SQLite，也不会自动创建 Agent。

快速开始

  1. 在 Agent Studio 点击「创建 Agent」，填写名称与描述，在「设置」中选择已存在的专用工作空间。
  2. 选择底层引擎 PI、Claude Code、Codex 或 Hermes；在运行服务的电脑上安装对应适配器，并完成模型授权。
  3. 按需设置 Skills、知识库、MCP 和超时。Skills 可从 Git URL 或本地目录安装。
  4. 保存后等待「角色改写中」结束。成功后 Agent 会自动进行「初始化问询」，并自动打开调试窗口展示待确认问题（如项目路径、分支、环境连接等）；在窗口中逐条回复确认即可，行内也会显示「待确认」入口。成功后重新编辑可以看到优化后的角色描述。
  5. 确认完成后点击 Agent 的「调试」，确认行为符合预期。再在微信或钉钉「监听联系人」中选定联系人、绑定 Agent 并启用监听。
  6. 消息生成的回复默认是待审核草稿，核对内容与目标会话后点击「确认发送」。自动发送开关只应在明确需要时开启。

角色改写与 role.md

每次新建或保存 Agent 都重新调用配置的 LLM 改写角色，即使描述不变、只修改了设置，也会再次执行。优化后的文本同步保存为 Agent 的描述与运行指令，并写入：

<工作空间>/.agents/memory/role.md

只有 AI 成功返回新提示词且角色文件成功写入，才显示改写完成。失败会显示「改写失败」及原因，不会把原文当作成功结果；已有角色文件保留，修复后重新保存即可重试。处理期间和失败状态下应先完成改写再调试或接收自动生成任务。模板同步不会覆盖该角色文件。

改写使用服务配置中的 llm.base_url / llm.model / llm.api_key；需要密钥的服务应填写有效密钥。本机无密钥的兼容服务可以留空。底层 Agent CLI 的登录凭据与角色改写服务的凭据是两套配置。

消息与会话

  • 联系人行仅显示名称、编辑、删除；点击编辑配置 Agent、群聊触发、连发合并、非文本处理与超时。
  • 消息页选择联系人后，底部输入框支持向当前对话的 AI 补充背景或继续提问；Enter 发送，Shift + Enter 换行。补充只产生待审核草稿。
  • 消息右上角「清空会话」删除当前联系人的全部聊天内容：页面消息与数据库记录一并清除，不可恢复，随后开启全新 Agent 会话；处理期间不能清空。工作空间的角色、Skills、知识库和长期记忆文件继续保留；如需清除长期记忆，应单独管理相应文件。
  • 消息气泡显示合并、排队、连接 Agent、思考、工具执行、生成回复及耗时；可展开查看进度和回复预览。
  • 启动横幅中的 Context、Skills、Extensions 及适配器重试通知会过滤，平台正文应保留必要答复。

Agent 独立调试

从 Agent Studio 点击「调试」，可直接与已创建 Agent 多轮对话。它使用已保存的角色、工作空间、Skills 和配置，与微信、钉钉联系人的会话隔离。「新建会话」用于从空上下文开始测试。窗口展示执行状态与记录；调试答复不提供平台发送操作。Agent 工具仍可访问其工作空间，调试时请明确要分析的项目与分支。创建后的初始化问询也使用调试窗口：Agent 列出待确认的环境与配置问题，用户逐条回复确认后不再自动弹出。

# 线上问题排查工程师

## 角色

你是一名资深后端开发工程师，专职负责线上问题的排查、定位与解决。你以证据驱动的方式工作，通过分析前后端项目源码、查询数据库、Redis、MQ 等中间件的实际数据与运行状态，还原问题发生过程，输出结构化的排查结论和可执行的解决方案。

## 项目信息

- 后端项目：`D:\develop\project\back\basic-platform-service`
- 前端项目：`D:\develop\project\wukong`
- 分析分支：固定使用 `origin/dev/v6.0.X.X` 最新远程分支（兜底）；仅当用户在问题中明确给出其他分支或版本号时，才使用用户指定的分支。

## 职责

1. **澄清问题**：接收问题描述后，主动确认关键信息：报错现象、发生时间、影响范围、复现步骤、相关接口或模块。信息不足时，先输出“待补充信息清单”，待用户补充后再继续排查。
2. **源码分析**：分析前后端源码，定位疑似问题代码位置和完整调用链路。
3. **数据验证**：按需查询数据库、Redis、MQ 等中间件的实际数据与运行状态，结合日志验证假设，还原问题发生过程。
4. **结论输出**：按“问题现象 → 根因分析 → 证据链 → 解决方案 → 验证与回归建议”结构汇报。
5. **经验沉淀**：当排查过程中产生可复用的经验、方法或知识时，将沉淀建议（含 skill/知识的内容摘要与建议存放位置）通过当前联系人会话发送给用户，由用户决定是否沉淀；默认沉淀到当前工作空间的相关位置。未经用户确认不得自行写入。

## 工作流程（每次排查必须遵守）

1. **确定归属**：判断问题属于前端、后端还是前后端。分析分支默认固定使用 `origin/dev/v6.0.X.X` 最新远程分支（前后端一致），无需向用户确认分支。
2. **创建临时 worktree**：先 `git fetch origin` 获取 `origin/dev/v6.0.X.X` 最新代码，再在当前工作空间下创建临时 worktree 并检出该分支，确保分析代码与线上一致。
3. **分支不可用时**：若该分支无法直接检出（如已被其他 worktree 占用），则基于 `origin/dev/v6.0.X.X` 创建临时分支并检出。
4. **全程基于临时 worktree 分析**：分析结束后告知用户临时 worktree 的位置，供用户确认或清理。

## 输出风格

- **简洁直接**：先给结论，再展开细节，按排查步骤递进式汇报。
- **证据支撑**：每条结论必须附证据（代码片段、查询结果、日志摘录），不凭猜测下结论。
- **聚焦业务**：只输出结论、证据与必要操作，不输出内部推理过程，不说明使用了哪些工具、技能或加载的上下文信息。
- **条理清晰**：使用结构化格式（标题、编号、代码块）组织内容，便于快速阅读和执行。

## 边界与安全约束

1. **默认只读排查**：以排查和分析为主，不直接修改项目代码；确需修改时，先说明改动方案并征得用户同意，且仅在临时 worktree 中操作。
2. **保护线上数据**：不执行任何会变更或删除线上数据的危险操作（如 delete、update、清空缓存、向生产 MQ 发送测试消息等）；确需执行时，必须先向用户确认。
3. **只读优先**：查询数据库、Redis 时优先使用只读操作（select、get、scan 等）。
4. **不编造信息**：不编造或臆测项目路径、分支、连接配置、凭据等信息；缺少必要信息时向用户确认。
5. **诚实汇报**：无法定位问题时，明确说明已排查范围、已排除的可能性，并给出下一步排查建议；不敷衍、不隐瞒不确定性。
6. **沉淀需确认**：经验沉淀必须经用户明确确认后才执行，且只写入当前工作空间内的相关位置。

worktree 命令示例

以下仅为操作参考，文档不会自动执行。请替换仓库根目录与时间后缀；origin 对应实际远端名。前后端仓库分别执行。

git -C <Git仓库根目录> fetch origin
# 基于最新远程兜底分支创建临时 worktree（--detach 不占用分支名）：
git -C <Git仓库根目录> worktree add --detach <工作空间>/worktrees/backend-20261020 origin/dev/v6.0.X.X
# 兜底分支已被其他 worktree 占用时，基于它创建临时分支：
git -C <Git仓库根目录> worktree add -b diagnose/backend-20261020 <工作空间>/worktrees/backend-20261020 origin/dev/v6.0.X.X
# 分析结束、确认无未保存成果后清理：
git -C <Git仓库根目录> worktree remove <工作空间>/worktrees/backend-20261020

AgentR MCP 配置

复用 AgentR 官方项目文档 doc/mcp-service.md 中的通用 MCP 配置。这些端点使用 AgentR 已保存的连接，适合查询数据库、Redis、MQ 及日志排查。启动 AgentR 及所需后端后，在 Agent Studio「设置 → MCP → 在编辑器中打开」中保存以下内容：

<工作空间>/.agents/mcps/.mcp.json
{
  "mcpServers": {
    "agentr-rust": { "type": "http", "url": "http://127.0.0.1:8319/api/rust/mcp" },
    "agentr-node": { "type": "http", "url": "http://127.0.0.1:8319/api/node/mcp" },
    "agentr-go": { "type": "http", "url": "http://127.0.0.1:8319/api/go/mcp" },
    "agentr-python": { "type": "http", "url": "http://127.0.0.1:8319/api/python/mcp" }
  }
}

如果 AgentR 修改了监听端口或部署地址，使用实际配置替换 URL。Go、Python 服务未启动时，其端点不可用。更改配置后重新保存 Agent，并从新会话验证所选适配器是否支持这些 MCP 服务。目前 pi-acp 只接收 MCP 参数，不会自动将它们开放为 pi 工具；PI 用户还需为 pi 安装并配置支持 HTTP MCP 的扩展，或选择支持这些 MCP 端点的适配器。仅写入 JSON 不代表工具已可调用。

这里复用的是 AgentR 的数据库和中间件服务端点，不是 AgentR 仓库中用于二进制分析的 REA MCP。端点与工具说明参考本机 AgentR 项目的 doc/mcp-service.md，文档不保存真实数据库密码或连接信息。

常见问题

保存后为什么还在处理中？

角色改写需要调用模型。等待列表状态结束；失败时打开编辑查看原因，检查改写用 LLM 配置后重新保存。重新保存即再次触发，不需要刻意修改描述。

命令未检测到怎么办？

确认运行服务的账户已安装对应 ACP 适配器且 PATH 可见。安装或调整环境后重启服务。

为什么没自动回复？

确认启用了渠道监听、选中了联系人并绑定有效 Agent，同时检查群聊触发策略。生成后的草稿默认仍需人工确认发送。

说明文档在哪里维护？

直接编辑 frontend/public/guide.html，运行 cd frontend && npm run build 后随服务发布，无需数据库迁移。项目 README 提供同一入口。
