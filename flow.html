🔀 链路变体

同一套链路，4 种运行形态（由配置 / JEV 结果 / 入口不同而分流）

🅰 自动发送链路 auto_send=true

新消息监听→ 生成回复generate()→ status=sent跳过审核→ send_reply直接发送

与主链路差异：生成结果不经「待审核」，_handle() 中直接 _dispatch() → send_reply()。适合低风险场景。

🅱 JEV 拦截链路 质量门禁

生成候选→ JEV 复审全部不合格→ 重写一次携带失败原因→ 复审再失败→ 🚫 blocked 拦截禁止自动发送→ 人工确认可强制发送

典型场景：候选含「转账 / 密码 / 红包」等敏感内容。前端显示红色「已拦截」徽标与 忽略拦截，仍要发送 按钮，责任在人。

🅲 对话测试链路 POST /api/chat

前端 DirectChat→ /api/chat不走连接器→ generate()同一引擎接口→ 同步返回回复

用途：验证提示词 / JEV / 未来 RAG 效果。与主链路共用 ReplyGenerator，但不经过连接器与人工审核队列。

🅳 RAG 扩展链路 预留

generate()→ 检索知识库向量匹配→ 拼装上下文历史+知识→ LLM 生成→ 下游不变复审/审核复用

扩展方式：新增 RagReplyGenerator(ReplyGenerator)，在 build_engine() 注册即可；JEV 复审、审核链路全部自动复用，其余代码零改动。
